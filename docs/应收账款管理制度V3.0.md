## 第一章 总则

**第一条** 为规范公司应收账款管理，加速资金回笼，降低坏账风险，明确各部门及人员职责，结合公司实际情况及数字化管理系统（以下简称"系统"）的功能设计，特制定本制度。

**第二条** 本制度适用于公司所有因销售业务产生的应收账款管理，包括客户授信、结算管理、逾期预警、催收执行、考核奖惩、压单管理、坏账处理等全流程管理。

**第三条** 应收账款管理的基本原则：
（一）谁经办、谁负责：营销师为其经办客户应收账款的第一责任人；
（二）过程可控：通过系统实现应收账款全生命周期的可视化跟踪；
（三）及时预警：系统在欠款即将到期及逾期后自动推送预警通知；
（四）分级催收：按逾期天数实行三级升级催收机制；
（五）数据驱动：所有催收操作、考核计算、审批流转均在系统中完成并留痕。

## 第二章 术语与定义

**第四条** 本制度中下列术语的含义：

（一）**应收账款**：因销售业务产生的、客户尚未支付的货款，以ERP系统中的欠款记录为准。

（二）**催收任务**：系统按客户+逾期日期维度自动生成的催收工作单元。同一客户、同一到期日逾期的所有欠款聚合为一个催收任务；同一客户在不同日期逾期的欠款会生成不同的催收任务。每个催收任务包含客户名称、欠款总额、欠款笔数、最大逾期天数等信息。

（三）**催收明细**：催收任务下关联的每一笔欠款单据，包含单据编号、单据金额、剩余未收金额、到期日期、逾期天数等信息。

（四）**准入规则**：系统判断欠款是否应纳入催收的规则框架，包括逾期天数规则和最大欠款单数规则，各规则可独立启用或禁用。

（五）**升级催收**：当催收任务在规定时限内未得到有效处理时，按层级向上级转移催收责任的机制。

（六）**压单**：客户指定其名下某些结算单（订单）暂时不参与催收结款，其他结算单照常结款催收的管理措施。压单分为长期压单（无限期）和期限压单（指定天数）两种类型。

（七）**核销**：确认客户已回款，将对应的欠款单据标记为已结清的操作。需由营销师提交核销申请，经结算会计（出纳）确认后方可生效。

（八）**差异处理**：催收过程中发现实际欠款与系统记录不一致、客户对账存在争议等情况时，将任务标记为差异状态并流转至财务处理的流程。

（九）**OA审批**：通过系统内OA审批模块发起的线上审批流程，审批通过后系统自动执行后续操作（如更新ERP授信信息）。

（十）**钉钉工作通知**：系统通过钉钉平台向相关人员推送的业务通知消息，包含催收提醒、升级通知、审批通知等。

## 第三章 组织架构与职责分工

**第五条** 应收账款管理涉及以下角色，各角色职责如下：

### （一）营销师（marketer）

1. 应收账款的第一责任人，负责其经办客户的日常催收工作；
2. 在系统中执行催收操作：提交核销申请、申请延期、标记差异；
3. 收到催收任务和预警通知后，在规定时限内跟进处理；
4. 上传催收凭证（回款截图、客户确认函等）；
5. 发现异常情况及时向营销经理汇报或发起升级。

### （二）营销经理（marketing_manager）

1. 负责辖区内应收账款的监督与指导；
2. 接收升级催收任务（L1级），在规定时限内处理；
3. 审核辖区内客户授信申请（OA审批第一节点）；
4. 对营销师的催收工作进行日常检查和考核；
5. 协调处理重大催收差异和客户纠纷。

### （三）财务部门

财务部门包含以下与应收账款管理相关的岗位：

**1. 往来会计（current_accountant）**
- 审核客户授信申请（OA审批第二节点）；
- 处理催收差异：核实欠款差异原因，解决差异后退回营销师继续催收；
- 定期核对ERP系统与公司账务的应收账款数据。

**2. 结算会计/出纳（cashier）**
- 确认或拒绝营销师提交的核销申请；
- 核实回款到账情况，确保核销金额与实际回款一致。

### （四）总经理（general_manager）

1. 接收授信申请的抄送通知，掌握重大授信情况；
2. 审批坏账核销等重大事项（待坏账管理模块上线后执行）；
3. 对应收账款管理工作进行总体监督。

**第六条** 系统管理员（admin）负责系统的配置维护、角色权限分配、准入规则参数调整等技术管理工作，不参与具体业务操作。

## 第四章 客户授信与信用额度管理

**第七条** 客户授信实行"先授信、后发货"原则。所有赊销客户必须完成授信审批后方可享受账期或滚单结算方式。

**第八条** 授信类型：
（一）**账期授信**：客户在约定的账期天数内支付货款；
（二）**滚单授信**：客户在约定的滚单额度内循环使用信用；
（三）**压单授信**：客户指定其名下特定结算单暂不结款，被指定的结算单在压单期间不参与催收，其他结算单照常结款。

**第九条** 授信申请流程：
（一）**申请发起**：由营销师或营销经理在系统中提交"客户授信申请"OA审批单，填写客户名称、授信类型、授信条件等信息，并上传客户营业执照（首次授信必须提供）；
（二）**审批流程**：营销经理审批 → 往来会计审批 → 系统自动更新ERP客户授信信息；
（三）**抄送**：审批通过后自动抄送总经理；
（四）**生效**：审批通过且系统自动完成ERP更新后，授信即生效。

**第十条** 营业执照管理：
（一）首次授信必须提供客户营业执照照片；
（二）如客户营业执照正在办理中，可申请延期补交，补交时限为审批通过后7个自然日；
（三）系统在第3天和第6天自动发送补交提醒通知；
（四）逾期未补交的，按每日10元标准考核，直至补交完成。

**第十一条** 信用额度动态管理：
（一）系统根据ERP客户档案中的"最大欠款单数""最大欠款天数""最大欠款金额"等字段进行实时监控；
（二）当客户欠款超过授信限额时，系统可通过准入规则自动触发催收；
（三）授信额度需要调整时，应重新提交"客户授信申请"OA审批单。

## 第五章 货款结算方式与到期日计算

**第十二条** 公司货款结算方式分为以下三类：
（一）**现款现货**：发货时即时收款，不产生应收账款；
（二）**账期结算**：按约定的账期天数确定付款截止日；
（三）**滚单结算**：在约定的滚单额度内循环使用，超出额度的部分须即时支付。

**第十三条** 到期日计算规则：

（一）**账期客户**：到期日 = 发货日期（工作日期） + 客户账期天数
- 客户账期天数以ERP客户档案中"消费者到期天数"（consumerExpireDay）字段为准；
- 如客户档案中未设置到期天数，则默认账期为7天。

（二）**滚单客户**：滚单额度内的欠款不单独计算到期日，超出额度的欠款自发货之日起7天内须支付。

（三）**到期日判断公式**：逾期天数 = 当前日期 - 发货日期 - 最大允许天数
- 最大允许天数：账期客户取客户账期天数，其他客户取7天；
- 逾期天数 > 0 时，该笔欠款视为逾期。

**第十四条** 结算方式变更须通过"客户授信申请"OA审批流程，审批通过后由系统自动更新ERP客户档案中的结算方式和账期天数。禁止在ERP中直接手工修改客户结算信息。

## 第六章 逾期前预警机制

**第十五条** 系统建立逾期前预警机制，在欠款即将到期时主动推送预警通知，帮助营销师提前介入催收。

**第十六条** 预警规则：
（一）系统每日自动扫描所有未收款的欠款记录；
（二）筛选条件：未逾期且5天内到期的欠款（含今日到期）；
（三）预警等级分为三级：

| 预警等级 | 条件 | 紧急程度 |
|---------|------|---------|
| 今日到期（today） | 到期日 = 当日 | 最高 |
| 高度预警（high） | 1-2天内到期 | 高 |
| 中度预警（medium） | 3-5天内到期 | 中 |

**第十七条** 预警通知推送：
（一）系统按营销师维度合并推送：将同一营销师负责的所有即将到期欠款合并为一条通知；
（二）通知渠道：钉钉工作通知；
（三）通知内容包含：客户名称、单据编号、欠款金额、到期日期、剩余天数等关键信息；
（四）营销师收到预警通知后，应在当日主动联系客户确认付款安排。

**第十八条** 预警提醒历史：系统自动记录每次预警提醒的时间、涉及单据和接收人，支持按客户名称和日期范围查询历史记录。

## 第七章 逾期催收流程

### 第一节 催收任务生成

**第十九条** 系统每日自动执行催收任务生成流程，按以下步骤操作：

（一）**数据同步**：从ERP系统获取所有未收款的欠款记录；
（二）**数据富化**：补充压单标记、客户限额信息，计算逾期天数；
（三）**压单排除**：标记为压单的欠款不参与催收（详见第九章）；
（四）**准入规则评估**：按启用的准入规则逐条评估，确定是否入催；
（五）**客户+逾期日期聚合**：按客户名称和逾期触发日期（到期日）分组，同一客户同日到期的逾期欠款归入同一个催收任务；不同到期日的逾期欠款分别生成不同的催收任务；
（六）**任务分配**：根据客户归属自动分配责任人（营销师）。

**第二十条** 准入规则框架：

（一）**逾期天数规则**：欠款超过到期日即触发入催；
（二）**最大欠款单数规则**：当客户欠款单数超过ERP档案中设定的最大欠款单数时，按发货时间排序，超出部分的单据触发入催；
（三）各准入规则可独立启用或禁用，由系统管理员在系统中配置；
（四）任务生成时记录触发的准入规则快照，便于审计追溯。

**第二十一条** 催收任务状态定义：

| 状态 | 含义 |
|------|------|
| 催收中（collecting） | 任务已生成，营销师正在催收 |
| 差异处理（difference_processing） | 存在差异，已流转至财务处理 |
| 延期中（extension） | 已申请延期，暂缓催收 |
| 已升级（escalated） | 已升级至上级处理 |
| 待核销（pending_verify） | 已提交核销申请，等待出纳确认 |
| 已核销（verified） | 出纳已确认核销 |
| 已关闭（closed） | 任务结束 |

### 第二节 催收执行

**第二十二条** 营销师收到催收任务通知后，应在24小时内登录系统查看任务详情并开始催收。

**第二十三条** 催收操作类型：

**（一）提交核销**
1. 适用场景：客户已回款，需确认结清；
2. 操作方式：在系统中选择催收明细，填写核销金额和备注，提交核销申请；
3. 后续流程：任务状态变更为"待核销"，由结算会计（出纳）确认；
4. 核销确认：出纳核实回款到账后确认核销，任务完成；如回款不符可拒绝核销，任务退回"催收中"。

**（二）申请延期**
1. 适用场景：客户承诺延期付款；
2. 操作方式：在系统中选择催收明细，填写延期天数、上传凭证（如客户延期付款承诺书）；
3. 延期限制：单次延期最长不超过30天；
4. 后续流程：任务状态变更为"延期中"，延期到期后系统自动恢复为"催收中"；
5. 延期到期提醒：系统在延期到期前3天和前1天分别发送提醒通知。

**（三）标记差异**
1. 适用场景：催收过程中发现欠款金额、单据信息与实际情况不符；
2. 操作方式：在系统中标记差异并填写差异说明；
3. 后续流程：任务状态变更为"差异处理"，流转至财务（往来会计）核实处理；
4. 差异解决：财务核实处理完毕后，任务退回"催收中"，由营销师继续催收。

**（四）升级催收**
1. 适用场景：催收遇到困难，需上级介入；
2. 操作方式：在系统中发起升级，填写升级原因；
3. 升级路径和条件详见本章第三节。

### 第三节 升级催收机制

**第二十四条** 催收升级路径：

```
营销师（L0）→ 营销经理（L1）→ 财务（L2）
```

**第二十五条** 升级条件与操作：

（一）**L0→L1（营销师升级至营销经理）**：
- 营销师主动发起，或系统根据催收超时自动触发；
- 升级时需填写升级原因；
- 系统自动将任务分配给营销经理，并通过钉钉通知。

（二）**L1→L2（营销经理升级至财务）**：
- 营销经理发起升级；
- 升级时需填写升级原因；
- 系统自动将任务分配给往来会计处理。

**第二十六条** 退回机制：
（一）上级处理人认为任务不具备升级条件或需要原处理人补充信息时，可在系统中发起退回；
（二）退回时需填写退回原因；
（三）退回后任务恢复到退回前的状态，由原处理人继续催收；
（四）系统自动发送退回通知给原处理人。

### 第四节 法律催收

**第二十七条** 对于经多轮催收仍无法收回的应收账款，可启动法律催收程序：
（一）**发送催收函**：在系统中记录催收函发送情况，上传催收函附件；
（二）**提起诉讼**：在系统中记录诉讼立案信息，上传相关附件；
（三）**更新进展**：在系统中持续更新法律催收进展。

**第二十八条** 所有法律催收操作均须在系统中留痕，确保操作记录、附件、时间线完整可追溯。

## 第八章 催收考核与奖惩

**第二十九条** 考核起效日期：2026年4月23日起生成的催收任务纳入考核范围。

**第三十条** 考核按逾期天数分为三级，对营销师和营销经理分别考核：

### 一级考核（逾期3-5天）

| 角色 | 考核标准 |
|------|---------|
| 营销师 | 10元/任务 |
| 营销经理 | 20元/任务 |

### 二级考核（逾期5-7天）

| 角色 | 考核标准 |
|------|---------|
| 营销师 | 20元/任务（累加到一级考核之上） |
| 营销经理 | 40元/任务（累加到一级考核之上） |

### 三级考核（逾期7天以上）

| 角色 | 考核标准 |
|------|---------|
| 营销师 | 按欠款金额的70%考核 |
| 营销经理 | 按欠款金额的30%考核 |

**第三十一条** 考核计算规则：
（一）系统每日自动计算考核金额，生成考核记录；
（二）考核金额计算基准为催收任务的欠款总额；
（三）同一催收任务在不同考核级别之间累进计算（一级+二级+三级）；
（四）考核记录状态初始为"待确认"。

**第三十二条** 考核申诉：
（一）被考核人对考核结果有异议的，可在考核记录生成后5个工作日内，通过系统提交"考核申诉"OA审批单；
（二）申诉需写明申诉理由和相关证据；
（三）申诉审批通过后，考核记录状态更新为"申诉通过"，相应考核金额予以减免；
（四）申诉未通过或被驳回的，考核金额维持不变。

**第三十三条** 奖惩措施：
（一）连续30天无逾期催收任务的营销师，给予通报表扬；
（二）考核金额按月汇总，从当月绩效工资中扣减；
（三）年度累计考核金额超过5000元的人员，取消当年评优资格；
（四）主动收回已升级为L2级催收任务的，给予额外奖励。

## 第九章 压单管理

**第三十四条** 压单是指客户指定其名下某些结算单暂时不参与催收结款的管理措施，其他未被指定的结算单照常结款催收。压单期间的欠款不纳入催收范围。

**第三十五条** 压单类型：

（一）**长期压单（long_term）**：无限期暂不结款，直至手动解除；
（二）**期限压单（time_limited）**：指定暂不结款的天数，到期后系统自动解除并恢复催收。

**第三十六条** 压单申请流程：
（一）在系统中提交"客户授信申请"OA审批单，选择授信类型为"压单"；
（二）选择需要压单的结算单（可多选）；
（三）填写压单类型（长期/期限）和压单天数（期限压单须填写）；
（四）审批流程：营销经理审批 → 往来会计审批 → 系统自动执行；
（五）审批通过后，系统自动标记相关结算单为压单状态，并将对应的催收明细标记为“压单排除”。

**第三十七条** 压单期间的催收处理：
（一）被标记为压单的欠款明细自动从催收任务中排除；
（二）如排除后催收任务内无剩余明细，该催收任务自动关闭；
（三）压单期间不计算逾期天数，不产生考核。

**第三十八条** 压单解除：
（一）**期限压单**：到期后系统自动解除，定时任务每2小时扫描一次到期的期限压单；
（二）**长期压单**：须重新提交OA审批解除，或经管理层决策后由系统管理员操作解除；
（三）压单解除后，系统自动恢复相关明细的催收状态，重新计算逾期天数。

**第三十九条** 压单对账：
（一）系统在压单审批通过后自动执行压单对账，确保ERP结算单标记与系统催收明细标记一致；
（二）定时任务每日06:00执行一次全量对账，作为兜底机制；
（三）对账发现不一致时，系统自动修正并记录操作日志。

## 第十一章 报表与分析

**第四十四条** 系统提供以下应收账款管理报表：

（一）**催收概览**：实时展示催收任务统计（总数、各状态数量、逾期总金额等）；
（二）**我的待办**：按角色展示当前用户的待处理催收任务、待核销任务、差异处理任务等；
（三）**考核报表**：展示考核记录明细、按人员和月份汇总、考核状态分布；
（四）**逾期预警报表**：展示即将到期和已逾期的欠款分布、预警提醒历史。

**第四十五条** 报表使用要求：
（一）营销师应每日查看"我的待办"，确保不遗漏催收任务；
（二）营销经理应每日查看催收概览，掌握辖区内催收进度；
（三）财务部门应每周查看考核报表，及时确认考核记录；
（四）管理层应每月审阅催收统计和考核汇总，评估应收账款管理成效。

**第四十六条** 月度分析会议：
（一）每月召开一次应收账款分析会议；
（二）参会人：营销经理、财务负责人、总经理；
（三）会议内容：当月催收成果、逾期变化趋势、考核执行情况、重大异常事项；
（四）会议决议形成书面纪要，由财务部门存档。

## 第十二章 原始凭证管理

**第四十七条** 原始凭证范围：
（一）客户授信申请材料（营业执照、授信申请表等）；
（二）催收凭证（回款截图、转账凭证、客户确认函等）；
（三）延期凭证（客户延期付款承诺书等）；
（四）催收函、律师函、诉讼材料等法律文书；
（五）坏账核销审批材料。

**第四十八条** 凭证管理要求：
（一）**电子凭证**：通过系统上传，支持图片、PDF等格式，上传后由系统统一存储和管理；
（二）**纸质凭证**：由财务部门统一归档保管，按客户和时间分类编号；
（三）所有凭证须真实、完整、清晰，不得伪造或篡改。

**第四十九条** 凭证保存期限：
（一）正常结清的应收账款凭证，保存至结清后5年；
（二）坏账核销的凭证，永久保存；
（三）催收过程中的凭证，保存至任务关闭后3年。

## 第十三章 数字化系统操作规范

**第五十条** 公司应收账款管理全流程须在数字化管理系统中完成，各环节操作人员应熟练使用系统相关功能模块。

**第五十一条** 系统操作总则：
（一）所有催收操作（核销、延期、差异、升级等）必须在系统中完成，线下操作不作为有效记录；
（二）催收凭证必须通过系统上传，不接受线下提交的电子文件；
（三）系统操作日志作为催收工作的唯一权威记录，用于考核依据和审计追溯；
（四）禁止使用他人账号登录系统操作，每个操作人员须使用自己的账号。

**第五十二条** 各角色系统操作概要：

（一）**营销师**：
- 在"催收管理"模块查看和处理分配给自己的催收任务；
- 执行核销申请、延期申请、差异标记等操作；
- 上传催收凭证；
- 查看"我的待办"和预警通知。

（二）**营销经理**：
- 在"催收管理"模块查看辖区内所有催收任务的全貌；
- 处理升级至L1级的催收任务；
- 审核OA审批中的授信申请。

（三）**往来会计**：
- 处理"差异处理"状态的催收任务；
- 审核OA审批中的授信申请；
- 查看考核报表。

（四）**结算会计（出纳）**：
- 在"待核销"列表中确认或拒绝核销申请；
- 核实回款到账情况。

**第五十三条** 系统数据录入要求：
（一）核销金额须与实际回款金额一致，精确到分；
（二）延期天数须在1-30天范围内，且须与客户承诺的付款日期一致；
（三）差异说明和催收备注须如实、详细记录，不得空白或敷衍；
（四）凭证上传须清晰可辨，文件命名应包含客户名称和日期。

## 第十四章 系统通知与处理时效规范

**第五十四条** 系统通过钉钉工作通知和站内消息两种渠道推送业务通知。所有相关人员须保持钉钉在线状态，确保及时接收和处理通知。

**第五十五条** 通知类型与处理时效要求：

| 通知类型 | 触发时机 | 接收人 | 处理时效要求 |
|---------|---------|--------|-------------|
| 催收任务创建 | 系统自动生成催收任务后 | 责任人（营销师） | 24小时内开始处理 |
| 即将到期预警 | 欠款到期前5天内 | 责任人（营销师） | 当日内联系客户确认付款 |
| 催收升级 | 任务升级至上级处理 | 目标处理人 | 24小时内开始处理 |
| 延期到期提醒 | 延期到期前3天/前1天 | 责任人（营销师） | 收到提醒后当日跟进 |
| 核销结果 | 出纳确认或拒绝核销 | 责任人（营销师） | 收到结果后当日跟进 |
| 退回通知 | 上级退回催收任务 | 原处理人 | 24小时内恢复处理 |
| 考核生成 | 系统自动生成考核记录 | 被考核人 | 5个工作日内决定是否申诉 |
| OA审批通知 | 审批流转至下一节点 | 当前审批人 | 24小时内完成审批 |
| OA审批结果 | 审批通过/驳回/撤回 | 申请人 | 收到结果后按指示处理 |
| 抄送通知 | 审批通过后抄送 | 抄送人 | 知悉即可，无需操作 |

**第五十六条** 通知处理规范：
（一）收到通知后应在规定时效内在系统中完成对应操作；
（二）超过处理时效未操作的，系统将记录超时信息，可能触发进一步考核或升级；
（三）因系统故障或网络原因导致未能及时收到通知的，应在恢复后第一时间处理，并向系统管理员报告。

## 第十五章 OA审批流程规范

**第五十七条** 以下应收账款相关事项须通过系统OA审批模块办理：

| 审批类型 | 审批流程 | 审批通过后动作 |
|---------|---------|---------------|
| 客户授信申请 | 营销经理 → 往来会计 → 系统自动更新ERP | 更新客户信用额度/结算方式/账期 |
| 考核申诉 | 按系统考核申诉流程 | 考核记录状态变更，减免考核金额 |
| 客户档案修改 | 按客户档案修改流程 | 更新ERP客户基本信息 |

**第五十八条** OA审批通用规则：
（一）**发起**：申请人在系统中填写审批表单，提交后自动流转至第一个审批节点；
（二）**审批**：审批人在收到通知后24小时内完成审批（同意/驳回）；
（三）**转交**：审批人可将审批任务转交给同角色的其他人员处理；
（四）**撤回**：申请人在审批尚未处理时可撤回申请；
（五）**抄送**：审批完成后自动抄送相关人员。

**第五十九条** 以下事项**不通过**OA审批，直接在催收模块中操作：
（一）催收延期申请（营销师直接操作，最长30天）；
（二）催收差异标记（营销师直接操作，流转至财务处理）；
（三）催收升级（系统内一键升级）。

**第六十条** 审批时效管理：
（一）审批人超过24小时未处理的，系统可发送催办通知；
（二）审批记录完整保留审批时间线，作为合规审计依据；
（三）审批过程中的评论和意见须客观、专业，不得包含无关内容。

## 第十六章 数据安全与信息保护

**第六十一条** 客户信息保密：
（一）客户名称、联系方式、交易金额、欠款信息等均属于商业秘密，相关人员须严格保密；
（二）禁止向无关人员透露客户欠款信息和催收进展；
（三）禁止在社交媒体、公开场合讨论客户欠款情况；
（四）离职人员须在离职前完成客户信息的交接，并签署保密承诺。

**第六十二条** 系统访问权限管理：
（一）系统实行基于角色的访问控制（RBAC），不同角色只能访问其职责范围内的数据和功能；
（二）系统账号实行实名制，一人一号，禁止共享账号；
（三）密码须符合复杂度要求，定期更换；
（四）发现账号异常（如非本人登录、权限异常）须立即报告系统管理员。

**第六十三条** 催收凭证安全管理：
（一）通过系统上传的催收凭证（回款截图、签名文件等）由系统统一存储，仅相关角色可访问；
（二）禁止将催收凭证下载到个人设备或通过非系统渠道传输；
（三）凭证文件不得包含与催收无关的敏感信息。

**第六十四条** 数据导出与分享：
（一）导出催收数据、考核数据、客户信息等须经部门负责人批准；
（二）数据导出记录由系统自动留痕，包含导出人、导出时间和导出内容；
（三）对外提供数据（如配合审计、法律机构）须经总经理批准；
（四）数据文件传输须使用公司指定的加密渠道，禁止通过个人邮箱、即时通讯工具传输。

## 第十七章 监督与检查

**第六十五条** 财务部门每季度对应收账款管理情况进行专项检查，检查内容包括：
（一）催收任务处理时效和完成情况；
（二）考核执行情况和申诉处理情况；
（三）压单管理的合规性；
（四）原始凭证的完整性和规范性；
（五）系统操作日志的合规性。

**第六十六条** 系统管理员定期审查系统权限配置，确保角色与权限匹配，及时清理已离职或调岗人员的账号权限。

**第六十七条** 对违反本制度的行为，视情节轻重给予以下处理：
（一）轻微违规（如未及时查看通知、催收备注不完整）：口头警告并责令改正；
（二）一般违规（如超时处理催收任务、未上传催收凭证）：纳入绩效考核；
（三）严重违规（如伪造催收凭证、泄露客户信息、使用他人账号操作）：给予纪律处分，情节严重的依法追究法律责任。
